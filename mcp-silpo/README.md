# mcp-silpo

Підключення до MCP Сільпо для Cook 'n' Love: **mock-сервер** для розробки й тестів
та приклад клієнта. Реальний сервер: `https://mcp.silpo.ua/mcp`
([документація](https://ai-factory.silpo.ua/#developers)).

## Навіщо mock
Реальний сервер вимагає логін акаунтом Сільпо (телефон + OTP), віддає змінні дані й має ліміти (429).
Mock має ті самі назви tools, параметри та форму відповідей (знято з реальних викликів),
але віддає дані з `fixtures/` і не потребує авторизації. Для перемикання змінюється лише `SILPO_MCP_URL`.

## Запуск
```bash
uv sync
uv run python mock_server.py          # http://localhost:8000/mcp
SILPO_MCP_URL=http://localhost:8000/mcp uv run python client_example.py
uv run pytest
# або Docker
docker build -t mcp-silpo-mock . && docker run -p 8000:8000 mcp-silpo-mock
```

## Tools у mock
| Tool | Що робить |
|---|---|
| `silpo_get_my_shopping_cart` | id кошика (починати звідси) |
| `silpo_get_shopping_cart_by_id` | кошик, `branchId`, `deliveryType`, слот, підсумок, `validations[]` |
| `silpo_get_time_slots` | слоти доставки |
| `silpo_find_products_batch` | пошук до 30 товарів за назвами |
| `silpo_get_product_details` | картка товару (калорії, БЖВ) |
| `silpo_get_similar_products` | альтернативи |
| `silpo_get_my_food_restrictions` | харчові обмеження користувача |
| `silpo_add_cart_products` / `silpo_update_cart_products` / `silpo_remove_cart_products` | зміна кошика |

Реальний сервер має 40 tools; решта (доставка, лояльність, профіль тощо) у mock не реалізована.

## Важливо знати (з реальних викликів)
- Усі пошукові tools потребують контексту `branchId`, `deliveryType`, `timeslotStart/End`. Слот кошика може бути в минулому,
  а за описом tool'ів з недійсним слотом `stock` усіх товарів = 0, тому слот беремо зі `silpo_get_time_slots`.
- Для `weighted: true` товарів `step` і `quantity` у **кілограмах**; `displayRatio` лише для показу.
- `silpo_add_cart_products` повертає `success: true` навіть якщо товар не додано.
- `silpo_update_cart_products` приймає **абсолютну** кількість і id **рядка кошика**, а не `productId`.
- **Складу й алергенів у картці товару немає.** Є лише калорії та БЖВ (`attributes`). Це обмежує F11.

## Як користуватись у бекенді (читати цей розділ достатньо)
Імпортуйте `connect` і `SilpoClient` з `silpo_client.py`. Документацію Сільпо читати не треба.

```python
from silpo_client import connect

async with connect(os.environ["SILPO_MCP_URL"]) as silpo:
    found = await silpo.find_products(["молоко 2.5%", "яйця"])          # {запит: [товари]}
    result = await silpo.add_products_verified([(found["яйця"][0], 1)])  # AddResult
    if not result.ok:
        ...  # result.missing: не додалось, result.errors: помилки кошика (наприклад, більше за залишок)
```

| Метод | Що робить |
|---|---|
| `find_products(names, limit)` | пошук до 30 товарів; сам бере свіжий слот доставки |
| `ensure_valid_slot()` | виставляє в кошику найближчий доступний слот, якщо старий протух (адреса й магазин не міняються); викликається автоматично перед додаванням і перед `checkout_links` |
| `add_products_verified([(товар, к-сть)])` | додає й перевіряє перечитуванням кошика; вагові товари в **кг** |
| `set_quantity(product_id, к-сть)` | нова абсолютна кількість; `True`, якщо застосувалось |
| `remove_products([product_id])` | видаляє; повертає ті, що не видалились |
| `similar_products(товар)` | альтернативи (F10) |
| `food_restrictions()` | харчові обмеження користувача |
| `checkout_links()` | посилання на оформлення в Сільпо (не перевірено на реальному сервері) |
| `silpo.call("silpo_...", {...})` | будь-який інший tool напряму (потрібна документація) |

Перемикання mock <-> реальний сервер: змінна `SILPO_MCP_URL` (`.env.example`).

### Авторизація реального сервера
Для `https://...` `connect()` сам запускає OAuth 2.1 + PKCE (`silpo_auth.py`): відкриває браузер,
користувач входить на `auth.silpo.ua` (телефон + код), токен зберігається в `.silpo_tokens.json` (у `.gitignore`)
і оновлюється автоматично. Підтверджено на реальному сервері: виявлення, реєстрація клієнта та перехід
на сторінку входу. Повний цикл із кодом з SMS і виклики після нього перевіряє людина з акаунтом.

Це режим для розробки та скриптів (один користувач, токени у файлі). **Для вебсервісу** (багато користувачів)
замініть `FileTokenStorage` на сховище токенів у БД по користувачу, а `open_in_browser`/`wait_for_callback`
на редірект і маршрут `/callback` вашого бекенда (див. `make_auth` в `silpo_auth.py`). Токени не віддавати у фронтенд.

## Що ще не зроблено
- Токен-файл (`.silpo_tokens.json`) дає доступ до акаунта Сільпо: не комітити й не пересилати.
- Створення кошика для нового користувача (`exists: false`) не реалізоване; `ensure_valid_slot` не перевірений на реальному сервері, запис слота перевіряється `check_real_cart.py`.
- Вибір заміни відсутнього товару: за AI-частиною команди; клієнт лише віддає кандидатів (`similar_products`).
- Підбір фасування (F9): перерахунок «150 г» в упаковки і вагові товари (мають `weighted: true`, кількість у кг).
- Ліміти запитів (429): повторів із затримкою немає.
- Доставка й адреса, балабонуси: тільки через `silpo.call`.
- Алергени: сервер не віддає склад (див. нижче).
- Не перевірялось на реальному сервері: `add_products_verified`, `set_quantity`, `remove_products`
  (запис у кошик акаунта). Пошук, слоти та кошик (читання) перевірені.

## Умови використання Сільпо
Заборонено порівнювати ціни між мережами та масово збирати ціни чи асортимент.
Кешувати можна лише те, що користувач знайшов для свого кошика.
Fixtures — кілька товарів з реальних відповідей; не розширювати до копії каталогу.
